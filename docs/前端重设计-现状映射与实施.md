# 前端重设计：现状映射与实施记录

依据 `Basedoc/ui设计/天幕卫星仿真系统_前端交互设计方案.md` 与同目录示意图。方案 §0 要求先建功能与字段映射表再改 UI，本文就是那张表，同时记下设计取舍与本轮边界。

## 一、设计计划（令牌）

**颜色**（主色沿用现有仪表台口径，只补必须补的）

| 令牌 | 值 | 含义 |
|---|---|---|
| `--bg` | `#04080d` | 近黑深蓝主背景（方案 §8.1） |
| `--sel` | `#7fe3d6` | 当前选中、主要交互、关键状态（青） |
| `--sat1/2/3` | `#7fe3d6` / `#6fa8dc` / `#e8a33d` | 三星身份色，跨三维线、列表、图表一致（方案 §8.1 建议的青/蓝/琥珀） |
| `--event` | `#e8a33d` | 可见窗口与事件带 |
| `--bad` | `#d8604b` | 超限、失败 |
| `--na` | `#8ba0b3` | 未接入 / 未计算 / 暂不可用 |

身份色与状态色刻意用了同一批色值——这在仪表台上会撞。处理办法：**状态一律带文字，不靠颜色单独表达**（方案 §8.2 也是这么要求的），颜色只回答"这是哪颗星"。时间轴上的事件改用**形状**区分类别（§4.3），把琥珀这个色让给"窗口/告警"语义。

**字体**：数字走 Bahnschrift SemiCondensed（等宽数字，仪表台读数），中文走 HarmonyOS/思源黑。不引入第三种字体，不做全大写标签。

**布局**：桌面三栏工作台，中央三维为视觉主体。按方案 §2.1 给的空间区间取上界附近——顶栏 56、左栏 300、右栏 360、底部 116，两侧与底部均可收起；窄屏左右栏转抽屉。

**原则**：一个仿真时钟、一套数据查询层、缺值不填 0、每个操作有状态反馈、发光与边框只用在选中项上。

## 四、本轮边界（方案交付要求 5：缺数据/未实现清单）

1. **能源与热控无数据**：`power.csv` 五列、`thermal.csv` 四列在 259203 行里非空计数为 0，界面对应位置只能显示"未计算"。计算由能源/热控两位实现，接口已成文。
2. **改参数重新运行不做**：STK 对接未完成。
3. **地面轨迹为新增绘制**：数据侧有 `orbit_itrf.sublat/sublon`，此前三维没画。
4. **温度测点清单未定**：热控节点数量由方案 §11.2.12 的覆盖范围展开，最终名称与数量待总体设备清单统一，因此"关键温度"暂按单值槽位显示"未计算"。
5. **单星独立窗口（每星一个可拉出的窗口）不做**：方案 §5 的"单星查看"以右侧详情 + 相机聚焦实现，分屏另计。
6. **插值口径**：连续量按帧间线性内插统一提供，事件类不插值。
