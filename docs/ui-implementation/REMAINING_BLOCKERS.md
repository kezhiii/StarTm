### 第四/五轮审查提出、仍未闭环的（如实列，不粉饰）

- **E5 空态理由是写死的文案**：抽屉 ③⑤ 组与保存快照的「power 的 5 列整列为空…」「thermal 的 4 列…」是字符串常量，
  不由 `manifest` 推导。今天与事实相符，但能源/热控数据一旦交付，界面仍会说「未提供」。应由 `hasField()` + 列级抽样生成。
- **E8 导出没有字段多选**：对话框只有「目标 / 时间范围」，实现是自动挑非空列（比要求保守，但少了用户可控项）。
- **E9 稀疏列可能被抽样噪声删掉**：判「整列是否有值」只在区间内等距抽 64 个历元；一段只有几百秒有效的列会被当成空列剔除。
- **E10 取色仍有 18 处 off-token 字面量**：`index.html` 若干 `#eef5fb/#a2bad0/#9fb6cc/#9ecbff/#c78bd8`、超限点 `#d8604b`
  （按 §11.2 应给 `--status-error`）、XYZ 轴色 `#ff6b6b/#6bd0ff/#8ef0a8`，以及 6 处 `rgba(40,207,200,·)` 是
  `--border-active` 的第二份拷贝（token 一改即分叉）。验收台只比「15 个 token 到位」，不比「取色都来自 token」。
- **E12 断言强度残留问题**：`emptyTail` 算了但没断言（「恒空列必须 FAIL」没落地）；两处 `all(...)` 对空集合会退化为真；
  卡片读数与导出 CSV 同源（同一份 f32 + 同一个选中星），整体索引错位会互相抵消；文件名里的星号未与 `getSelectedSat()` 对账；
  保存/导出前后「选中星与时刻不变」取了值却没断言；个别截图前仍是固定 `sleep` 而不是等内容出现。
- **D6 的运行时证明仍缺**：`setCameraMode` 在桥缺失时回滚下拉框并提示，代码已改，但 harness 没有「桥为 null 时改相机模式」的用例。
- **天空视图网格数随切视角累积**：实测一轮阶段 3/5 走完后 `satelliteMeshes1D` 达 **61 个网格、其中只有 3 个可见**（跨阶段、跨视图累积；此前我按单次取样写成 12 个，低估约 5 倍）。
  `initFirstPersonView` 每次都往数组追加，旧的只隐藏不销毁，也没有按 `satCount` 去重复用。不影响读数正确性
  （断言已改成「只放大该放大的一颗」并如实记录网格数），属内存/清理类待办。
- **Phase 1 第 2 轮「不阻塞但请登记勿丢」的六项，此前一条都没登记**（现补上）：
  N1 页面视图（顶栏三档）会覆写相机模式下拉的选择，两者语义打架；N2 `ground` 分支没走 `refreshLayers()`，图层能力表不随之更新；
  N3 `satLabels3D/satLeaders` 未随清场复位（与上面的网格累积同源）；N4 RTN 指示器没标明它是 J2000 方向；
  N8 小窗的 R–T 投影方式没在界面上点明；N10 缺「晨昏轨道 ≤11.8°」这一句需求说明。
- **G3（第五轮已修）**：`phase-01` 曾有「引线只数对象个数、墙钟 fps 只打印不判定、`tabs` 测量不 `check()`、
  `check()` 里留一行死代码」四个弱断言。现改为逐条核对引线两端是否分别落在卫星与标签上、帧率改用「连续强制合成帧」口径判 25–120 tick/s（墙钟值只打印作参考，窗口被遮挡时它会读到 0.0）、
  五个标签页的内容与空态都判定。**G4（本轮更正）**：`IMPLEMENTATION_LOG.md` 曾写「右栏图表与标签绑定未动（属 Phase 2）」，
  而同一轮审查判 H2 未修——已按事实改写。

- **倍率与地球自转可能脱钩**（Phase 3 审查待查项）：`bridge.resume()` 会按内层 `#speed` 重算 `earthRotationState.speedFactor`，
