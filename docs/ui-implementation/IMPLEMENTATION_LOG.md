### 关于「89.5% 带外红点」的实测结论（没有靠改阈值糊过去）

### 为什么禁用自定义站址而不是"顺手实现重算"

`sim-data/ground_obs.csv` 的 `az/el/range/...` 是按 `meta.json` 里那一个站算死的，文件里没有站址维度。前端要重算就得在浏览器里再跑一遍 ECI→ECEF→ENU，那等于**在前端另起一套几何计算**去覆盖交付数据口径，超出前端改造范围，也容易和后端口径分叉。总指令 §3.3 给的正是这个选项："如果当前不能重新计算，则禁用自定义站址输入，并标明当前结果使用固定观察站"。所以按禁用处理，并把原因写在界面上。

1. **导出的 `utcg` 是一整列空的**。`exportRows()` 把 `utcg` 硬写进表头，但二进制列里根本没有这一列
   （manifest 只有数值列），于是 86401 行全空——而导出框上写着「只导出真实存在的字段」。
   修法：先查数据列在不在（`hasField`），在就用数据；不在就用桥按历元给出的真实时间戳
   （与走带条同一来源，新增 `hooks.utcAt`）；两者都没有就留空。
   配套断言：导出前 4000 行的 `utcg` 非空数必须 ≥3990，且逐行不同、形如 `YYYY-MM-DD HH:MM:SS`。
2. **加载只校验版本，不校验完整性**。一个版本正确但只有两颗星的 JSON 会把抽屉静默缩成 12 个输入框，
   再存出去就成了残缺场景；缺字段的文件更糟——它在 `renderBody()` 里抛异常，此时状态已经改了一半，
   而提示却写「界面保持原状态」。
   修法：新增 `checkScenario()`，在动任何状态之前整体校验（星数与基准一致、六个根数齐全且为数字），
   不合格直接拒。配套断言：少一颗星、缺 `a0` 两种文件都要被拒且 18 个输入框逐字不变。
3. 顺带：偏心率上界从自创的 0.999 改成物理的 `e<1`（开区间）、三个角 `[0,360)`、
   去掉没有依据的 `a0 ≤ 50000` 上限；设备表 `normal_w=0` 不再被 `||` 误判成「未提供」；
   抽屉里「太阳翼展开轴 ±Y_B」这句没有数据依据的话改成「未提供 · 需结构侧给出」。

### Phase 5（方法性盲区比缺陷本身更重要）
- 审查指出：DOM 字号审计看不到 canvas 里画的字。`chart.js` 的刻度与 `formation-inset.js` 的角标仍是 10.5 px，
  XYZ 指示器字母按 SVG 换算约 9.4 px——我的「最小字号 11 px」断言因此是假绿。
  修法：两处字号提到 11 px、指示器 `font-size` 0.26→0.31；**验收侧新增两类能失败的断言**：
  拦 `CanvasRenderingContext2D.prototype.font` 的 setter 记录运行时最小 px，以及直接读 `#axes text` 的渲染高度。
- 小窗 `formation-inset.js` 还留着改版前的三色（且索引顺序与界面相反）→ 改成 `import { SAT_COLORS }`，
  并新增一条像素级断言：从小窗 canvas 里取色，必须能数出三种新身份色。
- **三维模型本体的身份色是死代码**：`light-manager.js` 每帧按「开灯/可见」覆盖 `body.material.color`，
  所以我上一轮给本体上的身份色下一帧就被刷掉。这不是补一行能解决的——本体是状态通道（绿=地平以上、
  红=地平以下、黄=计划开灯），把它改成身份色就会丢掉灯光排程那一层信息。
  处置：删掉被覆盖的赋值（保留按星克隆材质，否则一颗星的状态会染红三颗），
  身份色明确由轨迹环、引线、标签与全部界面侧承担；界面里那句话说明也保留。
  验收断言相应改成两条：环/引线 = 三身份色；本体 ∈ 状态色集合且界面有文字说明。
- 4 处选中态还在用废弃的 `rgba(127,227,214,…)` 字面量 → 统一成 token 的 `rgba(40,207,200,…)`；
  `sat-model.js` 选中环同理。
