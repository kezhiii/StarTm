# 轨道数据文件是唯一驱动源，系统不做在线闭环

一个名叫"仿真系统"的东西里，姿态、热、能源的结果全部来自事先算好的文件，系统本身不参与任何闭环计算，只按时间轴回放。这么定是因为轨道参数会反复重算，导出链路必须做到改参数就能重新出一整套文件，而闭环要求进程间通信和步长同步，工作量翻倍且没有人在第一阶段提这个要求。接口按可流式追加设计，将来要接在线推送不用推翻格式。

## Considered Options

- 全离线文件回放（选定）
- 系统内自己递推轨道并闭环联算各分系统（否：StarTM 那套摄动递推与 CSV 通路是两条互不相干的管线，接起来等于重写）
- 混合，轨道离线、姿态在线（否：飞控仿真尚未开工，没有可对接的实时端）

## Consequences

- 5400 个点（90 分钟、1 秒步长）走文件加载，不走 StarTM 的推送缓冲，因为它的缓冲上限是 3600。
- 连续状态按 1 秒步长组织，事件按实际发生时刻单独成表，两者不混。连续状态跨分系统对不齐时取最近邻并标出滞后；事件不做插值也不做最近邻，否则持续时间短于采样间隔的频闪脉冲会被丢掉。

## Status

2026-10-09 依《天幕卫星V0总体设计方案》表3-6 修订，原先写的"各条时间轴一律最近邻"对事件不成立。
