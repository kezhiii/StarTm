# StarTM 以子系统的身份嵌进来，而不是被重写或被绕开

主界面自己写，StarTM 的前端用同源 iframe 装进来，父页面直接调它导出的函数。为此必须在 StarTM 上加一个外部驱动模式：让它自己的 requestAnimationFrame 循环停下来，时钟由主系统推进，选星由主系统指定。这么定是因为三维渲染、地球自转、轨道线、灯光和协议链已经在它那儿做完了，重写一遍不值；而它原本无法被指挥，入站消息只有取数和灯光两类，没有任何跳转或选星入口。

改动只发生在 `sim-system` 分支上，main 保持原样，且 StarTM 的改动与新系统的代码分开提交，方便单独回滚其中一类。

## Considered Options

- 同源 iframe 加外部驱动（选定）
- Python 桌面套浏览器控件（否：多养一个壳，指挥能力并不比 iframe 强）
- 新系统自己写三维（否：等于把地球、相机、轨道线、灯光全重来）
- 只嵌画面不指挥（否：那样点星联动做不到，实际就不是子系统了）

## Consequences

- 全系统只允许存在一个三维实例。点亮在前端执行、后端不广播状态，多嵌一份就会出现两份各自轮询排程、灯状态互不相同的界面。
- 切视角会销毁重建整个场景（`app.js:145`），外部驱动模式要一并处理这件事。
