# 保留灯光排程，因此数据库从可选项变成硬依赖，用 SQLite

灯光功能整条链保留，包括按挂钟时刻自动亮灭的排程。排程的权威存储在数据库里，后端处理灯光指令的顺序是写库、从库读回同步内存、再应用，所以只要排程在，数据库就不能关。StarTM 本身是"没有 MySQL 也能起"的，这条约束是保留排程换来的，不是它原来的设计。

选 SQLite 而不是仓库里 `alembic.ini` 配的 MySQL：单人开发，库里只有可再生的排程和协议日志，没有存量数据；省掉装库建表这一步，别人拿到分支能直接跑。建表走 `SQLModel.metadata.create_all`，alembic 那份原样留着不动。

## Consequences

- `create_async_engine` 现有的 `pool_size` 和 `max_overflow` 两个参数在 aiosqlite 上会直接抛 TypeError，要按方言跳过。
- 倍速档位与灯光排程的时刻基准要统一：以数据里的 14 位时间戳为准，后端那个从 2021-08-17 起算的假基准只留在排程内部，界面不显示。
