**审查范围**：项目全部 47 个源文件（45 JS + 1 HTML + 1 CSS），涵盖核心算法、渲染与场景管理、UI 与数据管理、架构与启动流程四大模块。

### 二、P0 — 关键 Bug / 逻辑错误

#### 2.1 匈牙利算法标号更新方向疑似反转

**文件**: `modules/image-processor.js` 第 764-768 行

匈牙利算法（Kuhn-Munkres）的标号更新阶段，`lx[u]` 和 `ly[v]` 的 slack 更新方向可能存在反转。标号方向一旦反转，算法无法收敛到最优匹配，卫星与形状点的全局最优匹配结果将不正确，直接影响星座"绘制图案"的视觉效果。此外算法缺少 `max_iterations` 安全限制，极端情况下可能无限循环。

```javascript
// 行 764-768 — 标号 slack 更新
for (let v = 0; v < n; v++) {
    if (!Sy[v]) {
        slack[v] = Math.min(slack[v], lx[u] + ly[v] - cost[u][v]);
        //                                   ^^^^^^^^^^^^^^^^^^^^^^
        // 若 cost 定义方向与此不匹配，标号会持续增大而非减小
    }
}
```

#### 2.2 BFS 队列使用 `shift()` — O(N^2) 性能瓶颈

**文件**: `modules/image-processor.js` 第 654 行

BFS 匹配使用 `Array.shift()` 出队，每次操作 O(N)。当卫星数量 N = 200 时，BFS 阶段复杂度退化为 O(N^2)，严重影响匹配速度。应改为环形队列或索引递增方案。

```javascript
const queue = [startIdx];
// ...
const u = queue.shift();  // O(N) — 每颗卫星出队都要移动整个数组
```

#### 2.3 `Math.asin` 参数未钳位 — NaN 风险

**文件**: `modules/math-utils.js` 第 68 行

`ecefToLocal()` 中 `Math.asin` 的参数未钳位到 `[-1, 1]`，浮点误差可能导致参数超出范围返回 NaN，后续传播到 Three.js 矩阵变换。

```javascript
const elevation = Math.asin(z / dist) * RAD;
// Math.asin 参数未钳位，dist 极小时 z/dist 可能 > 1 或 < -1
```

#### 2.4 方位角编队缩放存在 0/360 度环绕错误

**文件**: `modules/views/first-person.js` 第 226-267 行、第 474-514 行

当编队跨越方位角 0/360 度边界时，角度差值未规范化。例如 `local.az = 359, centerAz = 1` 时差值为 358 度（应为 -2 度），乘以 `FORMATION_SCALE = 5` 后变为 1790 度，卫星被放到完全错误的天空位置。CSV 和 WS 两个版本均受影响。

```javascript
// 行 261 — 角度差未规范化
const azR = centerAz * DEG + (local.az * DEG - centerAz * DEG) * FORMATION_SCALE;
//                           ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
//                           跨越 0/360 边界时差值接近 360 度而非接近 0 度
```

#### 2.5 `SAT_SCALE_CENTER = 1` 坐标比例错误 — 主星视角卫星不可见

**文件**: `modules/views/center-person.js` 第 152 行、`modules/interpolation.js` 第 276 行

卫星 ECI 数据以米为单位（LEO 轨道约 7,000,000 米），但 `SAT_SCALE_CENTER = 1` 未做缩放。地球模型半径 6378 单位（公里），相机远平面 20,000 单位。卫星位于约 7,000,000 处，完全超出相机视锥。

```javascript
// config.js 行 8
export const SAT_SCALE_CENTER = 1;  // 应为 RE_3D / RE_KM 或类似缩放

// center-person.js 行 152
const centerPos = { x: centerSat.X * SAT_SCALE_CENTER, ... };
```

#### 2.6 `mesh.material.disposed` 是无效检查

**文件**: `modules/light-manager.js` 第 157 行

Three.js 的 `Material` 类没有 `disposed` 属性，此检查永远为 `false`，是失效的安全保护。操作已 dispose 的材质会在 WebGL 内部产生未捕获的错误。

```javascript
if (!mesh.material || mesh.material.disposed || !mesh.parent) {
    return;  // material.disposed 永远为 undefined → 不生效
}
```

#### 2.7 `appState.domCache` 始终为 `undefined` — DOM 缓存完全失效

**文件**: `app.js`（全局问题）

`appState.domCache` 在 9 个位置被读取（`interpolation.js`、`view-update.js`、`first-person.js`、`center-person.js`），但唯一赋值位于死代码 `core/bootstrap.js` 中。所有读取处都有降级到 `getElementById`，但 DOM 缓存优化完全失效。在 60fps 动画循环中产生大量不必要的 DOM 查询。

```javascript
// interpolation.js 行 71 等 9 处
const domCache = appState.domCache;  // 始终为 undefined
const el = domCache ? domCache.get('coordDisplay') : document.getElementById('coordDisplay');
// 永远走 else 分支
```

#### 2.8 `changeSpeed()` 播放循环竞态条件

**文件**: `managers/playback-manager.js` 第 917 行、第 957-1018 行

`changeSpeed()` 通过 `cancelAnimationFrame` 取消旧循环，但若回调已进入微任务队列，新旧循环可能在一帧内同时执行，导致 `csvState.currentTimeIdx` 被双重递增。且 `changeSpeed` 完全重写了播放循环（123 行），与 `startCsvPlayback` 的循环是两套独立实现。

#### 2.9 WebSocket 连接状态竞态

**文件**: `managers/playback-manager.js` 第 639-725 行

`connectWebSocket` 的 `onclose` 重连逻辑与外部 `clearWsConnection()` 存在竞态。`onclose` 回调可能被清除后又被设置，导致意外重连或断连后无法正确清理。

#### 2.10 `hide()` 未停止 autoMatcher 定时器

**文件**: `modules/ui/constellation-panel.js` 第 616-619 行

面板隐藏时未停止 `autoMatcher`，`setInterval(tick, 1000)` 在后台持续运行。多次开关面板会累积多个未清理的定时器。

```javascript
function hide() {
    if (panel) panel.style.display = 'none';
    isVisible = false;
    // 缺少: if (autoMatcher) autoMatcher.stop();
}
```

#### 2.11 Escape 键监听器泄漏

**文件**: `modules/ui/constellation-panel.js` 第 366-370 行

`init()` 中注册在 `document` 上的 Escape 键监听器使用匿名函数，无 `removeEventListener` 路径。面板重建后会累积多个监听器。

#### 2.12 `slider.max` 空指针风险

**文件**: `managers/ui-manager.js` 第 64 行

`slider` 可能为 `null`（来自 `getElementById`），但未做空检查直接访问 `.max`，会抛出 `TypeError` 中断整个 UI 初始化。

### 三、P1 — 性能问题

#### 3.1 `applyAll()` 每帧全量更新所有卫星材质

**文件**: `modules/light-manager.js` 第 191-195 行

`applyAll()` 在 `third-person.js` 的更新函数中被每帧调用，对所有卫星逐一执行 `_updateSatelliteLight`。每次调用都动态查找 mesh 数组、访问材质属性。对数百颗卫星的巨型星座，这是渲染循环的严重瓶颈。建议改为脏标记增量更新模式。

#### 3.2 第三人称视角每帧 `getElementById`

**文件**: `modules/views/third-person.js` 第 137 行、第 192 行

此文件完全未使用 `domCache` 机制，每帧执行 `document.getElementById('coordDisplay')`。其他视角模块已有 domCache 降级逻辑。

#### 3.3 第一人称视角 2N 次密集坐标转换

**文件**: `modules/views/first-person.js` 第 222-267 行、`modules/interpolation.js` 第 108-216 行

第一遍计算编队中心方向、第二遍渲染卫星位置，两遍都对每颗卫星执行 `eciToEcef` + `ecefToLocal` 变换（含大量三角函数）。200 颗卫星 = 400 次/帧密集坐标转换。建议缓存第一遍结果。

#### 3.4 最近邻距离 O(N^2) 嵌套循环

**文件**: `modules/ui/constellation-panel.js` 第 228-237 行

`reMatch()` 中的最近邻距离计算，外层 50 次采样、内层全量遍历所有卫星。对数百颗卫星，每次校准阶段开销明显。建议使用 KD-Tree。

#### 3.5 Canvas 渐变对象每帧大量创建

**文件**: `modules/ui/constellation-panel.js` 第 832-839 行

每颗开灯卫星都调用 `createRadialGradient()`，200 颗卫星全开灯时创建 200 个渐变对象。建议缓存预渲染的发光精灵图。

#### 3.6 WS 数据队列 `shift()` — O(N) 出队

**文件**: `managers/playback-manager.js` 第 760-761 行

队列裁剪使用 `while > shift()`，`Array.shift()` 对 3600 上限的队列是 O(N) 操作。建议使用环形缓冲区。

#### 3.7 WS 渲染循环以 60fps 运行但有效更新仅 1fps

**文件**: `managers/playback-manager.js` 第 491-531 行

`RENDER_INTERVAL = 1000ms`（1秒1帧），但 `renderLoop` 使用 `requestAnimationFrame`（约60fps），其余 59 帧重复计算相同的插值进度。

#### 3.8 `farthestPointSample` 中 `splice` 性能问题

**文件**: `modules/math-utils.js`

`splice` 在大数组上是 O(N) 操作，采样阶段频繁调用导致性能退化。应改为 swap-and-pop 方案。

#### 3.9 星空球体几何精度过高

**文件**: `modules/star-field.js` 第 25 行

`SphereGeometry(10000, 64, 32)` 约 4096 个三角面，背景球体从内部观察 32x16 已足够，可减少约 75% 顶点数。

#### 3.10 视角切换三重渲染帧

**文件**: `app.js` 第 270-275 行

切换到主星视角时连续安排 3 次 `requestAnimationFrame` 渲染，场景状态在三帧之间无变化，第 2、3 次完全冗余。

#### 3.11 CSV 大数据集一次性创建百万对象

**文件**: `managers/csv-manager.js` 第 90-107 行

10000 帧 x 200 星 = 200 万个对象一次性创建，可能导致主线程卡顿数百毫秒。

#### 3.12 `MutationObserver` 全树监听

**文件**: `index.html` 第 287-296 行

监听整个 `document.body` 的所有子树变更来检测 Canvas 创建。初始化阶段每次 DOM 变更都触发回调。应改为自定义事件通知。

#### 3.13 灯光时间线 DOM 大量创建

**文件**: `modules/light-timeline.js` 第 214-249 行

为每颗卫星创建 DOM 元素（label + input + span），数百颗卫星产生大量 DOM 节点。应考虑虚拟化列表。

#### 3.14 `switchView` 频繁重复 `getElementById`

**文件**: `app.js` 第 133-136 行

每次视角切换都重新查询视角按钮和锁定组等 DOM 元素，应缓存引用。

### 四、P2 — 代码质量与潜在风险

#### 4.1 CSV 解析逻辑跨文件重复（3 处）

**涉及文件**: `csv-manager.js` 第 126-145 行、`ui-manager.js` 第 130-146 行、`csv-mode.js`

三处代码几乎完全相同的 CSV 文本解析逻辑。任何列定义变更都需同步修改三处，极易遗漏。应抽取为共享的 `parseCsvText(text)` 工具函数。

#### 4.2 日志方案不统一（3 种共存）

| 方案 | 使用者 | 调用次数 |
|------|--------|---------|
| `createLogger()` | 3 个文件 | ~10 次 |
| 自定义 `DBG` 对象 | 5+ 个文件 | ~30 次 |
| 原始 `console.log/warn/error` | 26 个文件 | **149 次** |

`createLogger` 实际采用率不到 7%，且自身存在 Bug：颜色模式下 WARN/ERROR 退化为 `console.log`（`logger.js` 第 73-84 行），导致浏览器过滤和错误监控工具失效。

#### 4.3 `constellation-panel.js` 主星状态提取逻辑重复 4 次

**文件**: `modules/ui/constellation-panel.js` 第 35-65 行、第 254-283 行、第 695-710 行、第 953-975 行

`getCurrentObsAngle()`、`getCurrentHillCoords()`、`render()`、`handlePatternUpload()` 四处都有 CSV/WS 分支判断和 GMST 计算，应提取为 `getChiefStateAndGmst()` 公共函数。

#### 4.4 `playback-manager.js` 需要拆分（1045 行，5 个职责）

| 职责 | 行范围 | 建议拆分为 |
|------|--------|-----------|
| CSV 播放控制 | 44-350 | `csv-playback.js` |
| WS 播放控制 | 355-558 | `ws-playback.js` |
| WebSocket 连接管理 | 636-819 | `ws-connection.js` |
| 页面可见性处理 | 592-631 | 合并入 ws-connection |
| 统一播放控制 | 824-1019 | 保留主文件 |

#### 4.5 输入校验缺失

**涉及文件**: `csv-manager.js` 第 129 行（时间戳未校验）、`ui-manager.js` 第 134-142 行（parseFloat NaN 未逐一检查）、`location-controls.js`

`parseFloat` 对无效输入返回 NaN 但不抛异常，NaN 静默传播到 Three.js 矩阵变换导致画面消失但无报错。

#### 4.6 `visibilitychange` 监听器累积泄漏

**文件**: `managers/playback-manager.js` 第 593-631 行

每次 WebSocket 断连/重连都注册新的 `visibilitychange` 监听器，旧监听器无法移除（匿名函数注册在 `document` 上）。长期运行后多个处理器同时工作。

#### 4.7 `interpolateSatellites()` 未校验 `sat_id` 一致性

**文件**: `modules/interpolation.js` 第 17-19 行

仅按数组索引匹配前后帧卫星，若后端返回顺序变化，会将卫星 A 的位置插值到卫星 B 上，导致视觉跳变。

#### 4.8 纹理 URL 配置不一致

**涉及文件**: `config.js` 第 78-81 行、`texture-loader.js` 第 6-8 行

两处定义了 `TEXTURE_URLS`，月球 URL 不一致（config.js 用 Wikipedia 源，texture-loader.js 用 GitHub 源）。应统一配置来源。

#### 4.9 `app-context.js` resize 监听器无法移除

**文件**: `core/app-context.js` 第 66-70 行

匿名箭头函数注册 resize 监听，无法后续移除。若 `createAppContext` 被多次调用会导致监听器累积。

#### 4.10 共享材质 `CENTER_SAT_MAT` 未 clone 直接使用

**文件**: `modules/views/center-person.js` 第 80 行

灯光管理器对该材质的修改直接污染了 `sharedResources` 中的共享材质。从星用了 `.clone()`，主星也应同样处理。

### 六、架构评估

#### 6.1 三次未完成重构地层堆积

项目存在明显的"重构地层"问题，每次重构创建了新抽象但旧代码未迁移、旧文件未删除：

| 重构方向 | 产物 | 状态 |
|---------|------|------|
| DI/Bootstrap 重构 | bootstrap.js, di-container.js, dom-cache.js | 已放弃，全部死代码 |
| Engine/RenderLoop 抽象 | engine.js, render-loop.js | 已放弃，全部死代码 |
| 视角/模式/UI 模块化 | view-manager.js, view-switcher.js, modes/*, ui/time-controls.js | 已放弃，全部死代码 |

结果是死代码与活跃代码比约 30%，两套并行封装共存（`app-context.js` vs `engine.js`，`animate()` vs `render-loop.js`）。

#### 6.2 `app.js` — God Object

`app.js`（495 行）承担过多职责：全局状态创建（行 30-63）、渲染循环（行 79-107）、场景初始化（行 110-121）、视角切换全部逻辑（行 124-306，180 行）、视图更新代理（行 322-330）、完整初始化编排（行 335-494）。

`switchView()` 一个函数就有 180 行，混合了 UI 更新、场景管理、相机控制。讽刺的是，`managers/view-manager.js` 中已有完整且更优的视角管理实现（193 行），但从未启用。

#### 6.3 `appState` — 全局可变共享包

`appState` 被直接传递给几乎所有模块，任何模块都能读写任意属性。创建时定义了 15+ 个命名空间，运行时被动态扩展（`appState.lightManager`、`appState.lightScheduleManager`、`appState.constellationPanel` 等）。模块间的耦合完全通过它隐式传递，是一个无类型的"全局变量袋"。

#### 6.4 事件监听器管理缺失

项目中有 5+ 处事件监听器使用匿名函数注册在 `document` 或 `window` 上，无清理路径：
- `index.html` MutationObserver（行 287）
- `app-context.js` resize（行 66）
- `constellation-panel.js` Escape 键（行 366）
- `playback-manager.js` visibilitychange（行 593）
- `ui-manager.js` 多个按钮 addEventListener

长期运行或热更新场景下会造成内存泄漏。
