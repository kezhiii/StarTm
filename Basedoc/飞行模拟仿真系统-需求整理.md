# 飞行模拟仿真系统 需求整理

依据 2026-10-08 编队总体方案讨论记录整理，交付给本系统的实现方。凡本次没有定论的，收在最后一节，不写进正文当要求。

## 一、这套系统是干什么的

显示整星状态。三颗星的飞行过程、姿态、各分系统的工作参数，最后都汇到这里来看。

轨道数据是所有下游仿真的驱动源。动画按轨道数据走，整星温度按时间序列的变化也是轨道数据推出来的。算法由各分析组自己做，原始数据从这里输出。所以本系统同时是三颗星仿真数据的出口和汇总显示的地方，界面架构和对外的数据接口由实现方定义，其他人按这个格式往里导。

## 二、界面要求

| 项 | 要求 |
|---|---|
| 窗口 | 至少 3 个，每颗卫星都能单独拉出一个窗口 |
| 单星窗口内容 | 该星的基本情况与飞行过程 |
| 姿态 | 必须显示出来，做到可视化。自转、翻板展开这类动画不作为硬要求 |
| 姿态数据来源 | 由飞行控制仿真驱动 |
| 数据面板 | 右侧一个大表格，列出卫星全部工作参数，并为分析层留出显示位置 |
| 状态可读 | 每个窗口一眼能看出这颗星当前在做什么，数据随时间推进实时刷新 |
| 实现语言 | Python 或 MATLAB 均可 |

## 三、对外接口

数据格式要提前定义好，定义完别人才接得进来，标准是对方拿到文件直接能用。具体字段与格式需和对接方当面商定，本系统只先提出需求。

| 对接方 | 本系统给出 | 本系统希望拿到 |
|---|---|---|
| 热仿真 | 轨道数据、时刻序列 | 按约定格式输出的整星温度结果，能在界面上看到随时间的波动 |
| 飞控 / 姿态仿真 | 轨道数据 | 姿态角或姿态矩阵，用于驱动模型朝向 |
| 能源仿真 | 太阳入射角、轨道数据 | 功率平衡结果 |
| 通信分析 | 星间距离及其变化 | 链路可用性与星间距离的对应结果 |

热管理的计算功能由热组做完后交过来集成，后端算，本系统负责显示。

## 四、实施顺序

先解决数据自动化，再解决界面。

1. 轨道参数一改就能自动重算并导出一整套数据文件，这一步不做界面也算完成。
2. 定义上述各接口的数据格式，与对接方确认。
3. 单星窗口与姿态显示。
4. 右侧参数大表格。
5. 接入热、姿态的回流结果做集成显示。

## 六、StarTM 现有代码能复用到什么程度

已有的部分：Three.js 场景渲染多星轨道与编队、逐时刻轨道数据导入、WebSocket 实时推送、播放控制、地面站可见性计算、太阳与月亮位置解算。

轨道数据格式现成，CSV 每行一颗星，列为 `sat_id, a, e, i, OMG, omg, f, X, Y, Z, Vx, Vy, Vz`，六根数与位置速度并存，可以直接作为接口的基础。

需要新增的部分：

| 需求 | 现状 |
|---|---|
| 每颗星一个独立窗口 | 只有第一人称、第三人称、中心视角三种切换，没有分屏渲染 |
| 姿态显示 | 全代码库无姿态量，需新增数据字段与模型朝向控制 |
| 右侧全参数表格 | 现有 stats-panel 只计算可见性窗口，不显示整星工作参数 |
| 外部仿真结果回灌 | WebSocket 现有两类消息，data 传逐时刻轨道帧并带当前步与时间戳，command 传控制命令。热、姿态结果没有对应的消息类型，需扩展并做时间轴对齐 |
