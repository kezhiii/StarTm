# 前端页面问题分析（ChatGPT 分享副本，照录）

来源：https://chatgpt.com/s/t_6ac91cfc930081918f720eeb6dcde86e
记录时间：2026-10-09。本文只作改造输入，逐条对照落实，不改写原意。

总判断：主要问题不是视觉效果不够炫，而是视觉表现、信息组织和实际操作之间没有形成良好配合。已具备卫星数字孪生的基本元素（深色星空、三维地球、轨道线、参数面板、时间轴），但更像"展示型大屏"，未达到"可读、可控、可分析"的专业工作台水平。

## 一、视觉层级不合理

1. 地球太小，核心区域利用不足。地球只占画面中间很小区域，四周大量空白星空；左右面板占据大量屏幕宽度，进一步挤压三维场景；卫星目标过小，难辨姿态、轨道位置和编队关系。建议把三维场景作为主视觉区域，按相机距离和目标数量自动调整地球与卫星的显示比例。
2. 左右面板视觉权重过高。左侧时间、数据源、步长、参数版本；右侧大量状态参数和曲线，两侧都是密集小字号加细分隔线，注意力被分散。左侧部分低频信息始终占固定空间；右侧把姿态、亮度、有效显示、能源、热状态连续排列，缺少优先级；标题、参数名、数值、单位之间对比不足。建议按"全局状态 / 三维场景 / 选中目标详情"三层组织，次要信息进折叠面板。
3. 字体太小，阅读成本高。参数名、数值、单位、状态标记挤在同一行；正文与辅助信息字号差不足；低对比蓝灰字不利快速阅读；过多细线与紧凑间距显得拥挤。建议关键数值用更醒目字号，次要说明降权但保持可读，不要为容纳更多参数一味缩字。

## 二、三维卫星场景

4. 轨道线和卫星目标不够突出。蓝色轨道线与地球边缘重叠、缺前后关系；卫星没有清晰视觉标记。建议用不同视觉编码区分实际轨迹、规划轨迹、参考轨迹、目标卫星，颜色要有含义而非装饰。
5. 缺乏清晰的目标选择和观察反馈。没有明显的选中高亮、目标标签、相机跟随指示；用户不易判断正在看哪颗星、右侧参数对应哪个对象。建议点击选中、悬停简要信息、选中后显示轨道与状态，并提供"跟随目标""返回全局视角"。
6. 多视角之间缺少明确切换关系。底部"全局轨道/编队近景"与相机控制、目标跟随、当前选中对象之间不直观。应设计为统一的视角模式，切换后保持目标状态与时间状态一致。

## 三、数据面板

7. 数据多但缺任务语义。没有回答三件事：现在怎么样（是否正常）、目标怎么样（姿态/位置/约束是否满足）、发生了什么变化（与规划值偏差多少、是否恶化）。能源与热状态显示"空值"，稳定标志与有效显示显示数值，呈现形式相近，需逐项阅读。建议分四层：

| 信息层级 | 应显示的内容 | 推荐呈现方式 |
|---|---|---|
| 全局状态 | 仿真运行、数据连接、异常告警 | 顶部状态栏 |
| 目标状态 | 位置、姿态、稳定性、任务完成情况 | 目标详情卡 |
| 任务指标 | 规划值、实际值、误差、约束状态 | 对比指标与趋势图 |
| 系统遥测 | 能源、温度、通信、设备状态 | 可折叠的遥测面板 |

空值不应只是普通文本数值，应区分"未接入""暂不可用""尚未计算""数据异常"，避免把没有数据误认为正常。
8. 参数曲线缺可解释性。图高不足；三条曲线含义只靠顶部小色块，缺图例名称；横轴时间标记、纵轴刻度与当前时刻关系不明确；未显示规划值与实际值偏差，也没有异常点提示。建议改成有语义的趋势图（规划值与实际值、当前误差与允许误差、编队几何指标及趋势），支持悬停查看时刻与精确值、点击图表定位仿真时间。

## 四、底部时间轴

9. 播放控制与时间导航混在一起。播放、暂停、倍速、视角切换、时间标记同处一条，没有分组。当前步数 464/1441、时间轴相对刻度、左上角绝对日期与仿真时钟，三个时间概念缺少对应关系。建议把播放控制、时间定位、视角模式分组，拖动时明确显示对应仿真时刻。时间轴上的黄色标记没有解释：若代表任务事件、轨道经过、告警或观测窗口，应提供图例、悬停提示和点击定位。

## 五、交互规范

10. 颜色有风格但语义不统一。青、蓝、黄各自表示选中、正常、规划轨迹还是事件标记不明确。应建立统一颜色语义，使同一颜色在三维场景、参数面板、时间轴中含义一致。
11. 面板占用固定空间，缺自适应。左右面板始终存在，三维场景无法充分利用空间。建议可收起、可调宽，并按屏幕尺寸与任务模式重排。
12. 缺少关键操作反馈。"已接入，重新装载"看不出数据重载是否有进度、是否可能失败、操作后如何反馈。播放状态、数据加载、参数切换、异常告警都应有明确反馈。

## 六、重设计建议

保留深色航天风格（星空、地球、轨道、青色科技风），重点转向以三维场景为中心、以任务状态为主线、以参数分析为辅助。推荐信息架构：顶栏（系统名·任务仿真 / 运行正常 / 数据时间·仿真倍率）＋左侧任务状态与目标列表（含搜索筛选选中）＋主三维场景（轨道与目标高亮，全局视角/目标跟随/编队近景）＋右侧选中目标（姿态稳定、位置/姿态/轨道、关键指标、误差趋势、实际值/规划值）＋底部仿真时间轴（当前时刻·总时长·1×）。

改造优先级：

| 优先级 | 改造内容 | 预期收益 |
|---|---|---|
| P0 | 放大三维场景、缩减空白和固定面板占用 | 立刻改善整体视觉重心 |
| P0 | 重组右侧参数，突出关键数值和异常状态 | 降低阅读与判断成本 |
| P1 | 完善卫星选择、轨道高亮和相机跟随 | 增强三维场景可操作性 |
| P1 | 重做时间轴分组、时间映射和事件标记 | 提升仿真回放效率 |
| P2 | 增加目标列表、趋势图联动和数据状态解释 | 提升分析能力 |
| P2 | 完善响应式布局、快捷操作和状态反馈 | 提升长期使用体验 |

结论：最需要的不是加特效或参数，而是重新分配屏幕空间、明确数据优先级、让三维场景与参数面板真正联动。只改三处的话：放大地球与轨道场景、重构右侧参数面板、让时间轴与目标选择联动。
