# 飞行模拟仿真系统 详细方案

口径来源：《天幕卫星V0总体设计方案》表3-6、表2-1，晨昏轨道仿真报告，以及 2026-10-09 敲定的设计共识（ADR-0001 至 0005）。本文只写做法，依据不再重复论证。

## 一、系统形态

主界面是新写的网页，StarTM 前端用同源 iframe 挂在里面，后端沿用 StarTM 的 FastAPI。所有对 StarTM 的修改只发生在 `sim-system` 分支上，main 不动。

```
serproject/
├── StarTM/                  # 分支上小改，见第四节
├── sim/                     # 新系统，全部新增
│   ├── index.html           # 主界面入口
│   ├── js/
│   │   ├── store.js         # 单一状态源 + 发布订阅
│   │   ├── bridge.js        # 调 iframe 里的 __simbridge
│   │   ├── loader.js        # 按类别拉取并解析数据文件（Web Worker）
│   │   ├── rtn.js           # 参考中心状态 → RTN 轴 → 各星 RTN 姿态
│   │   ├── panels/          # 参数表（配置驱动）
│   │   └── curves/          # 曲线（uPlot，CDN 引入）
│   ├── config/
│   │   ├── panels.json      # 列定义：列名、类别文件、单位、真值或占位
│   │   └── display.json     # 门限：仰角10°、半锥角1°、边长10m、漂移50m、太阳高度阈值(默认关)
│   ├── tools/
│   │   ├── make_synthetic.py    # 合成 24h 逐秒数据（链路打通用）
│   │   └── make_projection.py   # 主文件 → StarTM 14 列投影
│   └── test/                # RTN、四元数、投影格式的离线校验脚本
└── sim-data/                # 数据文件，按表3-6 类别拆分，git 不跟踪
```

## 二、数据层

### 文件按表3-6 的类别拆分，一类一个 CSV

全表 22 类拼成一个文件约 100 列、259203 行、300 MB 以上文本，谁也没法整份加载，而且热、能源、显示本来就不是一个人生产的。所以按类别拆，谁生产谁替换自己的文件，轨道文件永远不动。

| 文件 | 表3-6 类别 | 生产者 | 加载策略 |
|---|---|---|---|
| `time_ident.csv` | 时间与标识 | 杨宏俊 | 常驻 |
| `orbit_j2000.csv` | 绝对轨道状态 | 杨宏俊 | 常驻 |
| `orbit_itrf.csv` | 地固状态、瞬时根数、太阳同步状态 | 杨宏俊 | 按需 |
| `formation_rtn.csv` | 编队相对状态、构型几何、中心漂移 | 杨宏俊 | 常驻 |
| `attitude.csv` | 姿态状态、指向状态 | 杨宏俊（当前），后续飞控卫景 | 常驻 |
| `sun_eclipse.csv` | 太阳几何、地影状态 | 杨宏俊，能源郑译飞接手发电功率后扩展 | 按需 |
| `ground_obs.csv` | 目标观察状态、地面投影状态 | 杨宏俊 | 常驻 |
| `display.csv` | 显示计划、显示执行 | 罗新辉 | 按需 |
| `power.csv` | 能源状态 | 郑译飞 | 按需 |
| `thermal.csv` | 热状态 | 吕康正 | 按需 |
| `flight_ctrl.csv` | 飞控输入与执行、控制代价 | 卫景 | 按需 |
| `events.csv` | 区间与事件 | 各生产者追加自己的行 | 常驻（行数少） |

常驻组合计约 40 个数值列，Float32 存约 40 MB，浏览器可行。按需组切到对应验证分组时才拉。

### 自描述表头

每个 CSV 头三行固定：

```
# 列名:    sat_id, rel_s, utcg, q_x, q_y, q_z, q_w, ...
# 坐标系:  -,      s,     UTC,  J2000→本体, ...
# 单位:    -,      s,     -,    无量纲(归一化), ...
```

前端只认前两行的列名与坐标系，单位行供人读。这满足 3.1.5"同时记录坐标系名称和物理单位"，也避开 StarTM 投影文件那种只靠列序的约定。

`attitude.csv` 里同时放两套四元数：`q_j2b_*`（J2000→本体，杨宏俊的原始量）和 `q_rtn2b_*`（RTN→本体，本系统 `rtn.js` 从参考中心状态算出后回写）。界面显示指向用后者，原始量保留备查。

### 事件表

表3-6 只规定了"开始、结束、持续时间和触发原因"。首版列定义如下，待杨宏俊确认：

```
event_id, category, sat_id, t_plan_utcg, t_actual_utcg, duration_s, reason, params_json
```

`category` 取：可见区间、地影、构型切换、控制、点亮、熄灭、保护。频闪边沿必须走这张表，不得落在 1 秒网格上。

### StarTM 投影

`make_projection.py` 从 `orbit_j2000.csv` 裁出 14 列，输出单行表头的标准 CSV：`timestamp,sat_id,a,e,i,OMG,omg,f,X,Y,Z,Vx,Vy,Vz`。时间戳 14 位 `YYYYMMDDHHMMSS`。瞬时根数从 `orbit_itrf.csv` 取。投影文件是 StarTM 的专用产物，别的系统不许消费。

### 没有真数据之前

`make_synthetic.py` 按报告要素（a=6978.137 km、i=97.787669525°、RAAN=260.833199252°、历元 2026-09-13 04:00 UTC、NaturalHCW 1 km 等边三角形、相位 90°/210°/330°）生成 24 小时逐秒合成数据：两体 + HCW 解析解给轨道和构型；姿态给对地定向叠加一次 30 秒 15° 机动，四元数解析构造；太阳高度用 astropy 预算好写进 `ground_obs.csv`，前端不做天文计算。真数据到位后按类别逐个替换，界面不改。

## 三、主界面

### 布局

左侧 iframe 装 StarTM（唯一三维实例，默认编队全貌）。右侧纵向三块：当前选中星的单星窗口（数值加曲线）、参数大表、目标区昼夜曲线。星间距离与构型六量曲线放主界面底部，不属于任何单星窗口。选中某星 = 调 `__simbridge.selectSat(idx)`，iframe 里的相机转过去，右侧三块切到该星。

### 状态管理

单一 `store.js`，模块只订阅不互查。StarTM 的 `appState` 全局袋是前车之鉴，主界面不复制这个结构。

### 参数表

`panels.json` 按表2-1 八项分组定义列：

```
"姿态指向": { "来源": "attitude.csv,ground_obs.csv",
  "列": [ "q_rtn2b_*", "指向误差_deg", "目标入锥", "离轴角_deg" ] }
```

4.3 有当前设计值的列填真值并在 `panels.json` 标 `source: "4.3.1"`，只有 TBC/TBD 的留空。整星 120 kg、轨道平均功耗 210.91 W、显示峰值约 540 W、载荷峰值 ≤400 W 这些直接填。

### 三种特殊状态

| 状态 | 例子 | 显示 |
|---|---|---|
| 空值 | 热状态"未计算温度保留为空" | 单元格留空，悬停提示"未计算" |
| 退出 | 显示模式下计算载荷、星间通信、数传停止工作 | 灰底，标"已退出" |
| 滞后 | 某类别文件的时间轴落后当前时刻 | 照显旧值，角标滞后秒数，超 `display.json` 阈值变灰 |

### 曲线

uPlot（CDN，与 StarTM 引 three.js 的方式一致）。构型六量按米级精度画，边长误差 10 米、中心漂移 50 米的门限画成参考线。频闪边沿从 `events.csv` 取，画成竖线标记，不插值。

### 时钟与倍速

主系统是唯一时钟。1× = 1000 ms 一帧推进 1 秒数据，10× 和 60× 同理，档位标签按真实时间倍数标。StarTM 侧只被动接受 `setStep`。

## 四、对 StarTM 的修改（全部在分支上）

按改动量从小到大：

1. `server/db/session.py`：`pool_size`、`max_overflow` 在方言为 sqlite 时跳过（已实测不跳会 TypeError）。
2. `server/db/session.py` + lifespan：SQLite 下启动时 `SQLModel.metadata.create_all`，alembic 不动。
3. `server/fastapi_app/app.py`：挂 `StaticFiles` 指向 `sim-data/`，前端用 `fetch` + `DecompressionStream` 拉 gzip。
4. `web/managers/playback-manager.js`：加外部驱动模式。`externalMode` 为真时 rAF 循环不自行推进，暴露：

```js
window.__simbridge = {
  setStep(i), getStep(), setSpeedMs(ms),
  selectSat(idx), getView(), loadProjection(url)
}
```

5. `web/modules/views/center-person.js`：跟随目标从写死的 `sats[0]` 改为可指定星号。
6. `web/modules/sat-model.js`（新增）：1400×1200×600 mm 比例的长方体、±Y 两片太阳翼、−Z 面标记为发光面；在三个 view 的 mesh 构造处替换球体，并在逐星更新循环里对 `q_rtn2b_*` 或 `q_j2b_*` 设 `mesh.quaternion`。挂点现成：`third-person.js:84` 已有 `userData.satIdx`。
7. `index.html` 档位表与 `frameIntervalSec` 三处推导（`:55-66`、`:263-273`、`:922-928`）改成真实时间倍数。
8. 灯光、图案、协议代码不动，面板不隐藏。

每完成一项单独提交，提交说明以 `StarTM:` 开头；`sim/` 下的以 `sim:` 开头，方便单独 revert。

## 五、实施步骤与验收

| 步骤 | 内容 | 验收 |
|---|---|---|
| M0 | 打 tag、开分支、跑通现状 | `git tag v0-baseline`，`git switch -c sim-system`，StarTM 起服务浏览器可播 |

## 六、开工命令

```
git tag v0-baseline
git switch -c sim-system
```

提交分两类：StarTM 改动一次一提，`sim/` 新增一次一提。跑通后合回 main：

```
git switch main
git merge sim-system
```

未跟踪文件（`Basedoc/`、`CONTEXT.md`、`docs/`）先 `git add <具体路径>` 提交一次，纳入版本保护。禁用 `git add -A` 和 `git clean -fd`。
